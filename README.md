# 物联网平台工程实践：10 个模块

10 个可独立运行的模块，合起来是一条从设备到平台的链路：设备侧做协议编解码、边缘判断与升级投递，平台侧做检索问答、任务编排、质量评测、内容生产与工单。

每个模块只用 Python 标准库实现，无第三方依赖，自带演示入口与单元测试。

**平台侧**

| # | 模块 | 解决的问题 | 实现要点 |
| --- | --- | --- | --- |
| 01 | 文档问答 | 制度文档散落，答案还要能核对出处 | 中英混合切词、BM25 检索、句末对齐切块、句子级 idf 重排、带原文偏移的引用、`http.server` 接口 |
| 02 | 任务工作流 | 多步任务要按依赖顺序跑，失败要能重试，慢步骤不能拖死全局 | DAG 分层拓扑与环检测、按层线程池并行、节点超时、有界重试、执行轨迹 |
| 03 | 输出评测 | 改了实现或模板，说不清究竟变好还是变差 | EM/F1/BLEU/ROUGE-L/JSON 字段命中、bootstrap 置信区间、配对 bootstrap 的 p 值、符号检验、回归门禁 |
| 04 | 内容生产 | 批量生产时模板散乱、合规不可控、渠道超长 | 模板槽位校验、按渠道硬上限截断、分级审核与 PII 脱敏、优先级队列与指数退避、JSONL/Markdown 导出 |
| 05 | 客服工单 | 重复咨询占人力，工单字段靠手填，SLA 说不清 | 意图打分与阈值分流、多轮状态机与槽位追问、SLA 违约判定、JSONL 工单持久化 |

**设备侧**

| # | 模块 | 解决的问题 | 实现要点 |
| --- | --- | --- | --- |
| 06 | MQTT 接入 | 设备要按标准协议接入，断线重连后消息不能丢 | MQTT 3.1.1 报文编解码（变长 remaining length、QoS1 PUBACK）、主题通配匹配、retained 消息、持久会话离线队列与 packet_id 去重、设备影子 delta |
| 07 | Modbus 网关 | 现场设备讲 Modbus RTU/TCP，上位机要按寄存器语义读写 | CRC16(0xA001) RTU 与 MBAP 编解码、功能码/数量/地址边界校验、异常响应、多从站线程化 server 与客户端重试隔离 |
| 08 | 水务边缘监测 | 电池设备不能一直上报，得在端上判断哪段数据值得发 | EWMA + 双侧 CUSUM 变点检测（含暖机/确认/冷却）、13 字节二进制包 + CRC8、低功耗分项估算与寿命预测、坏包隔离 |
| 09 | OTA 升级 | 野外设备升级怕半包、坏包、断线、批次翻车 | 版本比较与清单签名（HMAC-SHA256）、HTTP Range 断点续传、下载状态机与分块校验、灰度分桶与失败熔断回滚 |
| 10 | 预测性维护 | 突发停机代价高，想从"事后修"提前到"提前换" | 迭代 radix-2 FFT 与 Hann 窗幅值谱、轴承故障频率（BPFO/BPFI/BSF）、谐波带能量占比诊断、健康度趋势与 RUL 外推 |

每个目录都有自己的 README，写清做法、验证结果和边界。

## 一条命令验证

```bash
./run_all.sh
```

逐个跑演示入口（`src/demo.py`，要求退出码 0 且有输出）、单元测试，最后单独对 01 的 HTTP 接口发一次真实请求并断言返回引用。当前结果：**10 个演示入口正常，251 项单元测试通过**（01=15、02=18、03=24、04=30、05=25、06=30、07=24、08=26、09=31、10=28）。

单独跑某个模块：

```bash
cd 06-mqtt-device-hub && python3 src/demo.py && python3 -m unittest discover -s tests -v
```

## 设计上的取舍

- **零第三方依赖**：全部标准库实现，`python3` 直接跑，不用装环境。检索用 BM25 而不是向量库，MQTT/Modbus 自己编解码，FFT 自己写。
- **外部依赖用本地替身**：没有真实硬件、broker、传感器与串口，但协议、状态机、重试与超时都是真的，可以用 socket/loopback 与单元测试验证行为。
- **可替换的接口**：生成、存储、审核规则、寄存器表都留了注入点，换真实实现只改一处。
- **每个模块都写边界**：做到哪一层、没做什么，写在各自 README 的最后一节。

## 边界

这 10 个模块是**可运行、可测试的工程练习**，不是生产系统：没有接真实硬件与外部服务，没有权限、集群、持久化数据库与可观测性建设，也没有在真实流量下标定过阈值。它们的价值在于把协议细节、算法与失败路径落到实处——能跑、能改、经得起追问。
