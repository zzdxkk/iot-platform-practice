# 09 · OTA 固件升级服务（Range 下发 + 设备状态机 + 灰度回滚）

## 解决什么问题
升级一次固件，失败一半是"传输"问题、一半是"流程"问题：设备在弱网里断点续传要不要从中间接上、包被中间人改了一个字节怎么办、刷完起不来怎么回滚、新版本先发给 5% 还是全量。这个工程把这些环节都做成有明确状态和拒绝分支的代码。

## 怎么实现
- `src/manifest.py`：`Version`（semver 比较，可用 `<`/`<=`）、`build()` 生成清单（version/size/sha256/min_battery）、`sign()/verify()` 对"键排序 + 紧凑分隔符"的规范字节做 HMAC-SHA256 并用 `hmac.compare_digest` 比较；`check()` 汇总签名、包体大小、SHA-256、电量、版本是否更高五类问题
- `src/delivery.py`：`parse_range()` 支持 `bytes=a-b` / `bytes=a-` / `bytes=-n`，拒绝多区间、倒序、越界；`serve()` 返回 206 + `Content-Range`/`Accept-Ranges`/`ETag`，单次下发不超过 `max_chunk`，并给分块 SHA-256
- `src/device.py`：状态机 `idle → downloading → verifying → flashing → rebooting → success / failed`；只接受连续偏移的块（乱序/重复直接拒绝）、分块哈希不符立刻判失败、长度不符拒绝收尾、`watchdog()` 判超时、`rollback()` 回旧版本并清缓冲
- `src/rollout.py`：SHA-256 分桶（同一设备永远同桶）、3 阶段 5%/25%/100% 放量、失败率超阈值且样本足够时自动熔断 + 回滚，熔断后禁止推进

## 跑起来
```bash
python3 src/demo.py                        # 清单校验、断点续传、升级/乱序/回滚、灰度
python3 -m unittest discover -s tests -v   # 31 项
```

## 验证
31 项测试覆盖：版本排序与非法版本、签名正确/换密钥/改字段/缺签名、正常校验、哈希被改、电量不足、同版本跳过、HMAC 稳定性；无 Range 全量、闭区间、开区间、后缀区间、单次上限、四类非法 Range、空固件；设备全流程、乱序块拒绝且缓冲不被污染、分块哈希不符、长度不符、状态非法调用、校验失败回滚、看门狗超时与 idle 不触发；分桶稳定、首阶段只放小比例、逐级推进至完成、失败率熔断与回滚、样本不足不熔断、熔断后推进报错。

## 边界
- 下发是纯函数模拟，没有真实 HTTP 服务、CDN、并发与鉴权；`serve()` 只给一个响应结构
- 设备侧是内存状态机，没有真正写 flash、没有双分区 A/B 切换实现（只表达回滚语义）
- 灰度是单进程内存统计，没有持久化与跨实例聚合，也没有按机型/地域分维度
- 没有差分升级（bsdiff）、没有压缩、没有断点续传的服务端会话；回滚只回版本号，不提供旧包
