# 10 · 旋转设备预测性维护（FFT 特征 + 轴承诊断 + RUL）

## 解决什么问题
设备不会"突然"坏，它先震、再抖、最后卡死。这个工程从一段振动采样里把这件事拆成可计算的三步：频谱里有没有轴承故障特征频率 → 健康度在往哪个方向走 → 照这个速度还剩多久到维护线。

## 怎么实现
- `src/fft.py`：迭代式 radix-2 FFT（位反转 + 蝶形运算，长度非 2 的幂直接报错）、`ifft` 共轭回算、Hann 窗、单边幅值谱（按窗增益与 N/2 归一，正弦峰值≈幅度）、频带能量、峰值搜索、确定性伪噪声的多频合成信号
- `src/features.py`：RMS、峰度（超额峰度，正弦≈-1.5）、峰值因子、频谱重心、主导频率；`bearing_frequencies()` 用标准公式算 BPFO/BPFI/BSF（滚动体数、节径、球径、接触角）；`band_ratio()` 统计故障频率前 3 阶谐波带内的能量占比，超过 15% 判 `outer_race` / `inner_race`，否则 `healthy`
- `src/health_index`：把故障带能量、峰度、峰值因子压成 0–100 健康度，越界的项有上限，避免单一指标把分数打到 0
- `src/rul.py`：最小二乘斜率/截距、残差标准差；`rul()` 按"当前健康度到阈值的距离 ÷ 斜率"外推，趋势在变好时返回 `None` 而不是硬报数字；`rul_lower()` 用更陡的斜率给悲观估计；`alert()` 分 `stable/watch/maintenance_due/failed`
- `src/phm.py`：`Monitor` 分块喂振动 → 取特征 → 算健康度 → 多块后拟合趋势 → 输出诊断、RUL、悲观 RUL 与告警级别

## 跑起来
```bash
python3 src/demo.py                        # 故障频率、频谱峰值、健康 vs 外圈故障、退化与 RUL
python3 -m unittest discover -s tests -v   # 28 项
```

## 验证
28 项测试覆盖：冲激响应频谱全 1、长度非 2 的幂报错、FFT/IFFT 往返、Hann 端点为 0 且增益 (N−1)/2、纯直流谱、正弦峰值频率与幅值（分辨率内、幅值误差 <6%）、频带能量定位；单位正弦 RMS≈0.7071、峰度≈−1.5、峰值因子≈√2、全零信号不除零、重心跟随能量、BPFO<BPFI 且数值符合公式、谐波序列；健康信号判 healthy 且健康度 >90、外圈/内圈信号分别被正确归类、健康度显著下降；精确线性的斜率与 RUL（0.5 斜率/阈值 2 → 6 个周期）、变好趋势不给 RUL、已低于阈值给 0、悲观值小于名义值、样本不足报错、四档告警；`Monitor` 空报告、退化序列诊断+趋势+RUL、稳定健康序列不误报。

## 边界
- 信号是合成正弦叠加，不是真实加速度计数据；没有重采样、转速跟踪、阶次分析，转速变化时故障频率会漂
- 只做轴承两类故障的"带能量是否超阈值"，不是分类模型，也没有多故障并存与齿轮箱特征
- 诊断阈值 15%、健康度权重、RUL 外推都是工程经验参数，未在真实失效数据上标定；RUL 是线性外推，不表达加速退化
- 没有在线流式缓冲、没有窗口重叠与降采样，也没有持久化历史；一块 2048 点的 FFT 在本机毫秒级，未做实时性验证
