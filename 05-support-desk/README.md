# 05 · 客服工单系统（意图路由 + 多轮槽位 + SLA）

## 解决什么问题
客服自动化最常见的问题不是"答不上来"，而是答错、反复追问、该转人工时还在绕圈。这个工程把三件事做清楚：识别意图并按紧急度路由、缺参数时按槽位追问且有轮次上限、每个诉求落成带 SLA 的工单。

## 怎么实现
- `src/intent.py`：5 类意图（投诉/退款/售前/售后/FAQ）+ 关键词权重打分；词面没整体命中时用单字覆盖率给部分分（留下线索但不误判）；低于阈值回落 `unknown`；`route()` 按意图与情绪分派（投诉或强负面情绪直接转人工）
- `src/dialogue.py`：会话状态机 `new → asking → confirm → done / cancelled / handoff`；正则抽 `order_id`/`phone`/`reason`；只问缺的槽位并提示还剩几项；`max_turns` 到顶自动转人工；"取消/不用了"随时退出；已结束会话拒绝再处理
- `src/tickets.py`：`Ticket` 按意图定优先级（P1 1 小时 / P2 4 小时 / P3 24 小时）算出 `due_at`；`breach()` 区分"未处理超时"和"关闭但超时"；`TicketStore` JSONL 追加持久化、按优先级排队
- `src/service.py`：编排入口。FAQ 直接答不建单；投诉先落单再转人工（不让客户在机器人里绕圈）；其余建单后进多轮

## 跑起来
```bash
python3 src/demo.py                        # 意图/路由、多轮补槽位、SLA 超时、转人工
python3 -m unittest discover -s tests -v   # 25 项
```

## 验证
25 项测试覆盖：投诉优先级最高、退款/FAQ/未知分类、部分字匹配只给线索不判意图、负面情绪强制转人工、FAQ 路由到机器人；槽位抽取与追问、确认后结束、取消、超轮次转人工、已结束会话拒绝、手机号正则；P1/P2/P3 到期时间、未处理超时、按时关闭不超时、超时关闭算超时、JSONL 重载、按优先级排队、重复关闭报错；FAQ 不建单、退款建单并追问、未知不建单、投诉直接转人工。

## 边界
- 意图识别是规则 + 字面打分，不做语义理解；同义改写、长句多意图会漏，线上需要更强的规则或语义召回补位
- 会话状态只在内存里，没有跨进程共享；真实部署要把 session 放 Redis 之类
- SLA 只算时间不排班（没有工作日历、节假日、时区处理）
- 工单只是本地 JSONL，没有对接真实工单系统的 API、权限与通知
