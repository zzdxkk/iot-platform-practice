# 04 · 内容生产流水线（队列 + 审核 + 排版 + 导出）

## 解决什么问题
批量生产投放内容时，真正麻烦的不是"写一段话"，而是三件事：一批任务里有的会失败、会重复提交、要按优先级排队；生成内容必须先过合规审核；不同渠道（微博/公众号/小红书）有不同字数上限。这个工程把这条链路做成可测的状态机。

## 怎么实现
- `src/queue.py`：`JobQueue` 状态机 `queued → running → done/failed`；`idem_key` 幂等去重；优先级堆（优先级 + 就绪时间 + 入队序）；失败按 `base * 2^(n-1)` 指数退避并限次（默认 3 次）后转 `failed`；`clock`/`jitter` 可注入，退避时点能被测试精确断言
- `src/templates.py`：`{slot}` 占位符校验（缺字段/多字段/空值都报错）、按句末优先的 `truncate`、渠道字数限制（x 280 / 小红书 1000 / 公众号 2000）、话题标签清洗
- `src/moderation.py`：规则分级 `block > review > pass`（阻断优先于"字数太短"）、`re.Pattern` 规则可替换、手机号/邮箱脱敏
- `src/pipeline.py`：生产 → 审核 → 排版 → 汇总；被阻断的单独归档，单条模板错误不影响整批
- `src/export.py`：JSONL 归档 + Markdown 合集，文件名安全化

## 跑起来
```bash
python3 src/demo.py                        # 队列退避/幂等、审核分级、裁剪、导出
python3 -m unittest discover -s tests -v   # 30 项
```

## 验证
30 项测试覆盖：优先级与同级 FIFO、幂等去重、两次失败后的退避时点（1.0 → 3.0）、重试耗尽转 failed、退避窗口内取不到任务、drain 汇总；模板缺/多/空占位符、句末截断、渠道上限、未知渠道；审核 pass/review/block、阻断优先、短文本待审、手机号与邮箱脱敏、自定义规则；文件名安全化、导出文件落盘、流水线阻断与脱敏、单条模板错误隔离。

## 边界
- `generator` 是外部注入的函数（demo 里是简单字符串拼接），仓库不含任何外部服务调用
- 队列在内存里，进程重启即丢；没有分布式锁、没有死信队列、没有可视化
- 审核是正则规则，不做语义判定；规则表达力有限，误杀/漏杀都要靠人工复核（`review` 档就是给人工的）
- 导出只落本地 JSONL/Markdown，没有发布适配器，也没有重试后的幂等发帖
