# 08 · 水务边缘监测（EWMA/CUSUM 检测 + 功耗预算 + 二进制上报）

## 解决什么问题
电池供电的漏水/水压监测终端，两头都难：算法端要在噪声里认出"缓慢渗漏"而不是水锤尖刺；硬件端要算清楚两节电池能不能撑三年。云端还希望上报包尽量小，因为 NB-IoT 按时长和字节收费。

## 怎么实现
- `src/detect.py`：`Ewma`（α 平滑基线 + 暖机窗口，异常点不进基线）、`Cusum`（双侧累积偏移，k/h 可调，命中后归零）、`LeakDetector`（z 分数分级 normal/warning/alarm + 连续 N 点确认压掉单点尖刺 + 冷却窗口去重；冷却期不学异常值，避免"渗漏被学成正常"）
- `src/power.py`：`PowerProfile` 分项算睡眠（µA 级）/测量/发射的日耗，乘 0.85 降额估电池寿命，并给出"是否满足 N 年"的判定
- `src/packet.py`：13 字节定长上报包 `>BHIBhH` + CRC8（poly 0x07），版本号、序号、设备 ID、告警位、测量值（×100 存 int16）、电池电压；解码校验长度/CRC/版本；`uplink_bytes` 对比 JSON 与二进制体积
- `src/monitor.py`：`EdgeMonitor` 串起采样→检测→事件→打包；`replay()` 在服务端逐包解，坏包单独标记不中断整批

## 跑起来
```bash
python3 src/demo.py                        # 合成序列检测、功耗估算、包往返与坏包
python3 -m unittest discover -s tests -v   # 26 项
```

## 验证
26 项测试覆盖：EWMA 暖机不判定与慢跟随、样本标准差；CUSUM 检出持续上/下偏移、忽略小偏移；平稳序列零事件、阶跃被确认后报警、单点尖刺被压掉、冷却窗口内不重复报警；日耗为 0 的边界、日耗量级、寿命天数、目标年数判定；包往返、低电压位、CRC 篡改、长度错误、数值越界、设备 ID 越界、定长 13 字节、CRC8 已知向量（`123456789` → `0xF4`）；端到端事件计数、末包解码、坏包隔离、压缩收益。

## 边界
- 检测参数（σ、阈值、确认点数、冷却长度）是人工设定，没有在线自适应与阈值学习
- `sigma` 是常量而不是实时噪声估计；现场噪声变大时会误报，需要按站点标定
- 功耗是静态电流模型，没考虑温度对电池容量、自放电与低温保护的影响
- 上报包假设单跳直连；没有分片、重传、时间同步，也没有真正接入 NB-IoT/MQTT 传输
